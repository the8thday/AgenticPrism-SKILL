# Octet `Results.txt` import

Supported layout: tab-delimited per-sensor text with `Conc1`, `Start1`, `Stop1` headers and a `Time1\tData1` observation table. The adapter reads recorded values, checks finite monotonic time and header coverage, and copies raw files into the import directory. It does not read native `.frd` projects, determine phases, choose experimental units, interpolate references or perform reference subtraction.

The JSON import manifest needs `format=octet_results_txt`, `source`, `time_unit`, `concentration_unit`, `response_unit`, and a nonempty `traces` list. Each trace specifies `file`, `fit_group_id`, `sample_id`, `experiment_id`, `curve_id`, `sensor_id`, `cycle_id`, `association_start`, and `dissociation_start` in the declared time unit. `reference_file` is optional; `blank_file` and `blank_reference_file` (0.7.0) are optional together with it for double referencing. All their time points must match exactly; they become `reference_response`, `blank_response` and `blank_reference_response` columns and nothing is subtracted on import. The importer writes `data.csv`, `import_manifest.json`, `config.template.json`, and `source_files/`. The template intentionally leaves the assay approval flags unset.

Use [the public import manifest](../../../fixtures/kinetics_octet/octet_manifest.json) only as a format example. Its five-sensor Octet RED384 export and published reference rows are retained with source checksums in [the source manifest](../../../fixtures/kinetics_octet/source_manifest.json). The [300 s](../../../fixtures/kinetics_octet/config_300s.json) and [600 s](../../../fixtures/kinetics_octet/config_600s.json) configs analyze one experiment with different dissociation windows. They are sensitivity analyses, not independent experiments. Their source was already processed by the authors; the adapter makes no new reference subtraction.
